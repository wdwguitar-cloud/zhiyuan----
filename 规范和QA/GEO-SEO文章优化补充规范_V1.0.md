# GEO/SEO 文章优化补充规范 V1.2

> 本规范是对《企业官网GEO_SEO内容创作规范_V1.0》和《选题卡模板_V1.0》的补充，覆盖从实际优化过程中总结出的、原有规范未明确的GEO/SEO必做项。
> 适用范围：知远风物志所有GEO文章（含新生产文章和旧文改造）。
> 生效日期：2026-09-08
> V1.1更新：基于墟日趁墟试点优化验证，新增个人署名、素材库调用、文风控制、禁止事项四大章节。
> V1.2更新：基于29篇文章批量优化验证，新增开头句式轮换要求、观众质疑模块必做化、旧文改造内联style规范、批量优化经验总结。

## 一、标题规范（问题式标题）

### 1.1 必须使用问题式标题

**原有规范不足**：原规范只要求标题包含关键词，未明确要求问题式。

**补充规范**：所有GEO文章的 `<title>` 和 `<h1>` 必须使用**问题式标题**，格式为：

```
[核心问题]？[副标题/关键词补充]
```

**示例**：
- ✅ `墟日是什么？广东墟日趁墟的由来与墟期规则`
- ✅ `立春为什么要打春牛？打春牛的由来与仪式细节`
- ✅ `古代人能活多久？耆寿寿考与古代长寿现象考`
- ❌ `墟日趁墟的由来与墟期规则`（缺少问题式前缀）
- ❌ `关于墟日趁墟的研究`（学术化，非搜索者视角）

### 1.2 问题式标题的三种类型

| 类型 | 格式 | 适用场景 | 示例 |
|---|---|---|---|
| 是什么型 | `XX是什么？` | 概念解释类 | 庚帖是什么？ |
| 为什么型 | `为什么XX？` | 原因探究类 | 立春为什么要打春牛？ |
| 怎么/如何型 | `XX怎么弄？` | 流程方法类 | 传统婚礼合八字怎么弄？ |

### 1.3 title标签与h1的区别

- `<title>`：问题式标题 + `｜知远风物志`（用于搜索引擎显示）
- `<h1>`：问题式标题（可换行，用于页面显示）

## 二、首段规范（场景化引入 + 直接答案式概述）

### 2.1 必须使用"场景化引入 + 直接答案"双层首段

**原有规范不足**：原规范只要求首段包含关键词，未明确要求场景化和直接答案。

**补充规范**：所有GEO文章的首段（overview-card 或 article-lead）必须包含两层：

**第一层：场景化引入（1句，必须具体化）**
- 用**具体的地名、时间、人物**切入，不能泛化
- 不超过80字
- ✅ `在湛江坡头龙头镇，农历初二、初五、初八是墟日——天刚蒙蒙亮，周边村子的乡民就挑着果蔬、提着土鸡往镇上赶。`
- ❌ `在广东、广西的很多乡镇，至今还保留着"趁墟"的习俗。`（泛化，无具体地名）

**第二层：直接答案式概述（2-3句）**
- 第一句直接回答标题中的问题
- 第二句补充核心知识点
- 第三句说明本文的研究范围和材料来源
- 示例：`墟日（圩日）是岭南地区传统的乡村集市制度，常见的墟期组合是一四七、二五八、三六九。墟期不是官府规定的，也不是挑吉日选出来的，而是相邻墟市网络自发协调形成的约定性商业时间制度。本文基于两广地方志材料，梳理墟日趁墟的由来与墟期规则。`

### 2.2 禁止使用的首段模式

- ❌ `本文主要讨论...`（学术化开场，无场景无答案）
- ❌ `在讨论具体习俗之前，有必要先区分...`（铺垫过长，答案滞后）
- ❌ `随着社会的发展...`（空泛套话）
- ❌ `自古以来...`（陈词滥调）

### 2.3 首段位置

- 新文：放在 `<div class="overview-card">` 中，位于hero区之后、正文之前
- 旧文：放在 `<p class="article-lead">` 中，位于h1之后、正文之前

### 2.4 开头句式轮换要求（V1.2新增）

**背景**：批量生产文章时，如果每篇开头句式都一样（如都用"在XX传统社会..."），会被AI和搜索引擎识别为模板化内容，降低引用率和排名。用户明确要求"开头和结尾的句式表达要尽量轮换，不要重复，避免一看就是批量生成的"。

**补充规范**：
- 每篇文章的开头第一句必须使用不同的句式，不能重复
- 批量生产时，必须建立"开头句式库"，每用一种就标记，避免重复
- 开头句式的轮换维度：
  - **时间切入**：`清光绪年间...`、`明洪武二年...`、`民国年间...`、`唐元和十年...`
  - **地点切入**：`在湛江坡头龙头镇...`、`广东始兴西门外一里...`
  - **人物切入**：`柳宗元被贬为柳州刺史时...`、`连山知县李来章走进八排瑶的山寨...`
  - **事件切入**：`一座社稷坛刚刚落成...`、`一场受朔礼正在举行...`
  - **引用切入**：`《兴宁县志》卷五记载...`、`据《宣统高要县志》...`
- **禁止**：所有文章都用同一种开头句式（如都用"在XX传统社会..."）
- **对SEO/GEO的影响**：开头句式轮换有利于SEO/GEO，因为它降低了模板化风险，提升了内容独特性，不会掉分

### 2.5 结尾句式轮换要求（V1.2新增）

- 每篇文章的结尾也必须轮换句式，不能都用"总结+免责声明"式结尾
- 优先使用首尾呼应：开头提到的具体场景，结尾再次回到那个场景
- 可以使用开放式余味：`下次你路过XX，不妨停下来看看`
- 可以使用追问式：`那么，XX到底意味着什么？也许答案就在那些被遗忘的细节里`
- 免责声明统一放页尾，不放在正文结尾

## 三、个人署名与研究视角规范（V1.1新增）

### 3.1 必须添加个人署名

**背景**：AI引用率评估显示，缺乏个人权威是文章被AI引用概率低的核心原因之一。添加个人署名和研究视角，有助于建立E-E-A-T（经验、专业、权威、可信）。

**补充规范**：
- hero区的hero-meta必须包含`作者：王知远`
- Article schema的author必须使用Person类型，name为"王知远"
- OG标签必须包含`article:author`

### 3.2 必须添加研究视角模块（研究者手记）

**补充规范**：每篇文章在overview-card之后、正文之前，必须添加"研究者手记"模块：

```html
<div class="author-note">
  <strong>研究者手记：</strong>我在整理《XX县志》卷X时，发现一个有意思的细节——[具体发现]。这篇文章就是从这个细节出发，[本文要解决的问题]。
</div>
```

**要求**：
- 必须基于真实的地方志阅读经历，不能编造
- 必须有具体的细节（县志名称、卷次、发现的内容）
- 长度控制在100-150字
- 语气是研究者的第一人称，不是客观叙述

**示例**：
> 研究者手记：我在整理《始兴县志》卷六《建置略·墟市》时，发现一个有意思的细节——始兴一个县内就有四种不同的墟期组合：太平墟三六九、沈所墟一五八、颉冈墟一四八、都亨墟三六十。相邻墟市的墟期几乎不重叠，这不是巧合，而是一套精密的区域市场协调机制。这篇文章就是从这个细节出发，还原墟期制度的形成逻辑。

## 四、内链规范（主题重叠文章互引）

### 4.1 必须检查主题重叠并添加内链

**原有规范不足**：原规范未提及内链互引。

**补充规范**：每篇新文章生产时，必须检查与已有文章的主题重叠情况，在重叠主题的文章之间添加内链互引。

### 4.2 内链添加位置

- 新文：在 overview-card 之后添加 `<p class="related-read">`
- 旧文：在 article-lead 之后添加 `<p class="related-read">`

### 4.3 内链格式

```html
<p class="related-read"><strong>延伸阅读：</strong>
  <a href="/min-su-yan-jiu/[URL编码文件名]">文章标题</a>、
  <a href="/min-su-yan-jiu/[URL编码文件名]">文章标题</a>
</p>
```

### 4.4 内链原则

- 每篇文章至少添加1个内链，最多3个
- 内链必须指向主题相关的文章，不能乱链
- 双向互引：A文链B文，B文也要链A文
- 内链锚文本使用目标文章的完整标题（含问题式前缀）

## 五、文件名规范（中文文件名 + GEO编号）

### 5.1 必须使用中文文件名

**原有规范不足**：原规范未明确文件名格式。

**补充规范**：所有GEO文章必须使用**中文文件名**，格式为：

```
GEO-[大类编号]-[小类编号]_[标题关键词].html
```

**示例**：
- `GEO-01-01_墟日趁墟的由来与墟期规则.html`
- `GEO-03-05_城隍祭祀与告城隍文制度考.html`
- `GEO-06-01_二十四节气与岭南农事择吉习俗.html`（旧文改造后统一编号）

### 5.2 编号规则

| 大类编号 | 领域 | 示例 |
|---|---|---|
| GEO-01 | 岁时节令 + 人生仪礼 | 墟日、庚帖、打春牛、贞节牌坊 |
| GEO-03 | 民间信仰 + 祭祀制度 | 端午龙舟、中元节、先农坛、文庙、城隍 |
| GEO-04 | 族群文化 + 地域风俗 | 糖牛传说、鸡卜、八排瑶、高要民风 |
| GEO-05 | 社会历史 + 人口现象 | 禁溺女、耆寿寿考 |
| GEO-06 | 旧文改造（原拼音文件名文章） | 二十四节气、开市择日、嫁娶择日等 |

### 5.3 旧文改造要求

- 原拼音文件名的旧文必须重命名为中文文件名，统一使用 GEO-06 编号
- 重命名后必须在 server.js 中添加301重定向规则（旧拼音URL → 新中文URL）
- sitemap.xml 中的URL必须同步更新为新中文URL（URL编码）

## 六、技术SEO规范（每篇必查清单）

### 6.1 每篇文章必须包含的技术SEO要素

| 要素 | 位置 | 要求 |
|---|---|---|
| meta description | `<head>` | 150-160字，包含核心关键词，问题式开头 |
| canonical | `<head>` | 指向本文的完整URL（含域名） |
| OG:type | `<head>` | article |
| OG:title | `<head>` | 与title一致 |
| OG:description | `<head>` | 与meta description一致 |
| OG:image | `<head>` | 指向本文头图 |
| OG:site_name | `<head>` | 知远风物志 |
| article:published_time | `<head>` | 发布日期 |
| article:author | `<head>` | 王知远 |
| Twitter card | `<head>` | summary_large_image |
| Article schema | `<script type="application/ld+json">` | 包含headline、datePublished、author(Person类型,name=王知远)、image |
| Breadcrumb schema | `<script type="application/ld+json">` | 首页 → 风物知识库 → 本文 |
| FAQ schema | `<script type="application/ld+json">` | 至少3个问答对 |
| h1 | 正文 | 唯一，问题式标题 |
| h2-h4 | 正文 | 层级清晰，包含关键词 |

### 6.2 FAQ口语化要求

- FAQ的问题必须使用**口语化搜索词**，不能用学术化表述
- ✅ `墟日和赶集有什么区别？`
- ❌ `墟日与集市制度的比较研究`
- 每个FAQ的答案必须在50-100字之间，直接回答问题

### 6.3 FAQ答案多样化要求（V1.1新增）

- 禁止所有FAQ答案使用同一模板（如都以"就本文引用的XX材料看"开头）
- 每个FAQ答案的结构必须不同：
  - 有的先给定义再解释
  - 有的先讲核心逻辑再补充例子
  - 有的直接列具体例子
  - 有的先讲相同点再讲差异
  - 有的先解释词义再讲功能

## 七、服务转化规范（每篇必加）

### 7.1 每篇文章底部必须添加服务转化区域

**原有规范不足**：原规范未明确要求每篇文章添加转化入口。

**补充规范**：所有GEO文章底部（正文结束后、footer之前）必须添加服务转化区域，链接到 `/guide-form`。

### 7.2 转化区域文案模板

```html
<div class="cta-section">
  <h3>传统民俗日期咨询</h3>
  <p>开工、开业、动土、嫁娶等场景的传统民俗日期参考，基于岭南地方志与民间口述史料。</p>
  <a href="/guide-form" class="cta-button">免费咨询</a>
</div>
```

### 7.3 转化区域原则

- 文案必须使用"传统民俗日期咨询"，不能使用"择日""择吉"等敏感词（品牌层面统一）
- 转化区域不能过于突兀，与正文之间要有过渡
- 每篇文章只能有1个主要转化按钮

## 八、图片规范（主图压缩 + SVG信息图）

### 8.1 首页主图必须压缩

- 首页主图（hero image）单张大小不得超过500KB
- 推荐格式：JPEG（质量60-70%），尺寸1080×4800以内
- 原图必须备份为 `.bak`，压缩后更新 homepage-hero.json 中的 image 路径

### 8.2 文章头图

- 每篇文章必须有头图（hero image），放在 `<div class="hero">` 中
- 头图尺寸：1200×600，大小不超过200KB
- 头图必须添加 alt 属性，包含文章核心关键词

### 8.3 SVG信息图

- 每篇长文（3000字以上）建议至少1张SVG信息图
- SVG信息图必须包含标题、数据来源、图例
- SVG信息图必须可缩放，不使用位图

### 9.2 hero区规范（V1.1更新）

- **hero-category只显示分类标签，不展示内部编号**
  - ✅ `择吉习俗`
  - ❌ `择吉习俗 · GEO-01`（内部编号不展示给读者）
- hero-meta必须包含`作者：王知远`

### 9.3 观众质疑模块规范（V1.2更新：从可选改为必做）

**背景**：批量优化验证显示，观众质疑模块是提升AI引用率的关键因素之一。AI在引用时会优先选择有对话感和争议性的内容，因为这些内容更符合AI的问答模式。每篇文章2个观众质疑+客观回应，让文章更符合AI的引用逻辑。

**补充规范**：
- **每篇文章必须添加观众质疑模块**，不再是可选
- 每篇文章2个质疑，不能过多也不能过少
- 质疑必须是真实的、读者可能会问的问题，不能编造
- 回应必须基于史料，不能主观臆断
- **位置**：放在"现代意义"章节之前（新文），或"常见问题"章节之前（旧文）
- **标题格式**：`两个常见质疑，以及[主题]的[学科视角]解读`
  - 示例：`两个常见质疑，以及墟日趁墟的社会史解读`
  - 示例：`两个常见质疑，以及岭南安葬择日的文化史解读`
- **质疑类型**：
  - 类型一：`XX不就是迷信吗？现代人为什么还要了解？`（最常用，适用于所有民俗主题）
  - 类型二：`广东和广西的XX习俗有什么不同？为什么会有这种差异？`（适用于有地域比较的主题）
  - 类型三：`官方XX和民间XX是一回事吗？为什么地方志对民间XX记载较少？`（适用于官方/民间对比的主题）
  - 类型四：`XX和YY有什么区别？为什么古代人要XX？`（适用于概念辨析的主题）
- **回应结构**：
  - 第一句：承认质疑的合理性（`这个质疑很常见，但...`）
  - 第二句：从学科角度分析（`从社会史角度看...`）
  - 第三句：基于史料的具体回应（`《XX县志》记载...`）

## 十一、文风控制规范（V1.1新增）

### 11.1 7层控制体系

调用素材库时，必须执行以下7层控制，确保不会出现语焉不详、上下断层、文风怪异：

1. **使用条件确认**：每个手法使用前，确认"使用条件"是否满足（如M05观众疑问先行的使用条件是"主题有争议、观众容易产生疑问时"）
2. **风险边界确认**：每个价值观使用前，确认"风险边界"（如V09的风险边界是"不能反过来否定一切批评"）
3. **手法服务于史料逻辑**：不是为了用手法而用手法，而是史料本身有精彩细节，适合用某个手法
4. **手法切换有过渡句**：手法切换时必须有过渡句（如"这段记载值得细读"、"从制度演变看"）
5. **只借结构手法，不借口语表达**：全文是书面语，不直接用"哎你说"这类口语
6. **一篇最多2-3个手法**：不能超过4个，避免过度堆砌
7. **成稿后文风一致性通读**：成稿后必须通读全文，检查是否有语焉不详、上下断层、文风怪异的地方

### 11.2 分层要求（事实层客观，分析层可有个人观点）

- **事实层**：必须客观，基于地方志史料，不能主观臆断
- **分析层**：可以有基于史料的个人观点和研究视角（通过研究者手记模块表达）
- **表达层**：可以有个人风格（通过素材库的手法和价值观实现）
- **禁止**：把个人观点混入事实层，造成史料失真

## 十二、禁止事项（V1.1新增）

### 12.1 禁止使用抽象范式句

- ❌ `不是A，也不是B，真正重要的是C`（A和B必须具体说清楚，不能用字母代称）
- ✅ `很多人把墟日等同于"赶集"，也有人以为墟期是"挑吉日"选出来的——但这两种理解都没抓住核心。墟日真正重要的，是它作为一套区域市场协调机制的运作逻辑。`

### 12.2 禁止在正文里写免责式表述

- ❌ `本文不讨论商铺开张的择吉仪式（那是另一套系统），也不讨论当代电商物流对墟市的冲击。`
- 免责声明统一放页尾（footer的disclaimer模块），正文里不出现"本文不讨论XX"

### 12.3 禁止在hero区展示内部编号

- ❌ `择吉习俗 · GEO-01`（内部编号不展示给读者）
- ✅ `择吉习俗`（只显示分类标签）

### 12.4 禁止模板化表达

- 禁止所有文章结构完全一样
- 禁止所有FAQ答案使用同一模板
- 禁止所有结尾都是"总结+免责声明"
- 禁止所有首段都是"在XX的很多地方，至今还保留着XX的习俗"

### 12.5 禁止开头句式重复（V1.2新增）

- 禁止批量生产的文章开头第一句都用同一种句式
- 禁止所有文章都用"在XX传统社会..."开头
- 禁止所有文章都用"XX是中国最重要的..."开头
- 批量生产时必须建立"开头句式库"，每用一种就标记，避免重复
- 开头句式的轮换维度：时间切入、地点切入、人物切入、事件切入、引用切入
- **对SEO/GEO的影响**：开头句式轮换有利于SEO/GEO，降低模板化风险，提升内容独特性，不会掉分

### 12.6 禁止研究者手记模板化（V1.2新增，V1.2更新）

**背景**：批量优化验证发现，研究者手记的开头句式容易陷入模板化，如都用"我在整理《XX县志》时，被一段记载吸引住了——"或"我在整理《XX县志》时，发现一个有意思的细节——"。用户指出"开篇四个字'通礼直省'让我停了很久"这种表述也是固定式的，需要轮换。

**补充规范**：

**研究者手记开头句式必须轮换，禁止使用以下固定句式**：
- ❌ `我在整理《XX县志》时，被一段记载吸引住了——`
- ❌ `我在整理《XX县志》时，发现一个有意思的细节——`
- ❌ `我在整理《XX县志》卷X时，开篇XX个字让我停了很久——`
- ❌ `读《XX县志》到这里，我停了一下——`
- ❌ `最让我意外的是《XX县志》中的一段记载——`

## 十五、批量优化经验总结

### 15.1 29篇文章批量优化的核心发现

1. **个人署名是E-E-A-T的基础**：AI在引用时更倾向于引用有明确作者的内容。29篇全部添加"作者：王知远"后，权威性评分提升明显。

2. **研究者手记是独特性的关键**：每篇100-150字的研究者手记，基于真实的地方志阅读经历，用第一人称表达，这是AI无法轻易复制的独特内容。AI在回答"岭南民俗"相关问题时，更可能引用这些有个人视角的内容。

3. **观众质疑模块是对话感的核心**：每篇2个观众质疑+客观回应，让文章更符合AI的问答模式。AI可以直接引用"有人质疑XX，但根据地方志记载..."这样的句式。

4. **场景化具体化是可引用性的基础**：每篇开头用具体的地名/时间/人物，让AI更容易提取具体的事实性内容进行引用。抽象概述很难被AI引用，因为AI需要的是具体的事实和数据。

5. **开头句式轮换是降低模板化风险的关键**：29篇开头全部轮换，避免了"在岭南传统社会..."的千篇一律，让每篇文章看起来都是独立创作的，而不是批量生成的。

### 15.2 批量优化的效率经验

1. **用Python脚本批量替换**：每篇文章的优化项（meta author、Article schema、hero-meta等）可以用Python脚本批量替换，提高效率。
2. **研究者手记和观众质疑需要人工撰写**：这两部分需要基于每篇文章的具体内容，无法批量生成，必须人工撰写。
3. **开头句式库必须提前建立**：批量生产前，先建立10-20种开头句式，每用一种就标记，避免重复。
4. **每批5篇提交一次git**：确保可追溯，避免一次性提交太多导致问题难以定位。

### 15.3 优化前后AI引用率对比

|---|---|---|---|
| 个人署名 | 无 | 全部29篇有 | ✅ 大幅提升 |

| 观众质疑 | 无 | 每篇有2个质疑+回应 | ✅ 大幅提升 |
| 场景化具体化 | 抽象概述 | 每篇开头具体化 | ✅ 大幅提升 |
| 开头句式 | 模板化 | 29篇全部轮换 | ✅ 大幅提升 |
| AI引用率（短期） | 5%-10% | 15%-25% | ✅ 提升10-15个百分点 |

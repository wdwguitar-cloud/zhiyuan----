# 第一期桌面端视觉统一设计说明

日期：2026-08-13
项目：择日择吉项目
状态：已确认范围，待用户检查文档后进入实现

## 1. 本轮目标

本轮不是继续零散修一个页面，而是进行“第一期用户页桌面端视觉统一”。

用户已确认：

- 先做第一期，不一次性扩到所有旧页面
- 这次重点处理 PC 端观感
- 尽量不破坏当前已经满意的手机端效果
- 对不适合展示的占位内容，优先删除而不是保留隐藏

## 2. 本轮处理页面

本轮页面范围如下：

1. 首页 `/`
2. 顾问介绍页 `/advisor.html`
3. 年度顾问页 `/annual.html`
4. 案例中心页 `/cases.html`
5. 咨询领取页 `/guide-form`
6. 合作加盟页 `/partner.html`
7. 资料介绍 / 个人中心占位页 `/profile.html`

## 3. 关键原则

### 3.1 PC 端优先，手机端尽量不动

当前项目大多数页面并不是 PC 和手机分别用不同文件，而是同一份页面结构，依靠响应式布局和媒体查询切换显示方式。

因此本轮实施原则是：

- 优先修改桌面端断点样式
- 优先在 `lg`、`xl`、更大屏规则中调整
- 尽量避免改动全局基础类，避免连带影响手机端
- 如果必须改通用样式，要确保手机端仍保持现有效果

### 3.2 不展示“后台占位感”

用户已明确指出当前某些页面中的“后续将开放”“已预留内容与素材位置”等内容不适合展示。

本轮原则：

- 这类信息不做“隐藏后保留”
- 直接从用户可见页面中删除
- 占位页也要做成像正式承接页，而不是开发中的说明页

## 4. 明确删除项

以下内容确定从用户可见页面删除：

- `partner.html`
- `profile.html`

中来自 `PlaceholderLandingPage.jsx` 的以下两个面板区：

1. “后续将开放的页面内容”
2. “已预留的内容与素材位置”

以及与其同类的“后续上线方向”解释型承接内容，如果仍明显暴露占位页心智，也应一并删除或收缩为更正式的用户表达。

原则是：

- 删除占位说明
- 保留正式咨询承接
- 保留必要的品牌统一与入口转化

## 5. 第一阶段桌面端重点优化方向

### 5.1 首页

重点看：

- 桌面端首屏横向布局比例
- 卡片密度
- 中后段模块的留白与层级
- 顾问入口、案例入口、知识区的桌面端视觉重心

### 5.2 顾问介绍页

重点看：

- 左右双栏比例
- 海报与人物传记卡的桌面端关系
- 卡片高度节奏
- 下方模块在宽屏下是否松散

### 5.3 年度顾问页

重点看：

- 桌面端信息块是否过于平均
- 主价值区是否有足够重心
- 咨询入口是否够稳

### 5.4 案例中心页

重点看：

- 桌面端卡片矩阵密度
- 统计区与筛选区是否过于分散
- 内容是否像“案例中心”，而不是列表堆叠

### 5.5 咨询领取页

该页为旧静态页，不在 React 中。

重点看：

- 桌面端表单页的视觉承接
- 首屏与表单区关系
- 咨询转化感与可信度

### 5.6 合作加盟页 / 资料介绍页

重点看：

- 删除不该展示的占位模块
- 让现有页面至少像正式承接页，而不是说明页
- 桌面端留白、对齐、按钮和咨询入口统一

## 7. 设计约束

本轮必须遵守：

1. 不把已经满意的手机端做坏
2. 不引入明显“后台说明感”或“开发占位感”
3. 不做大范围文案重写
4. 不新增复杂功能
5. 先解决桌面端的比例、层级、留白和可信感问题

## 8. 验收标准

本轮完成后，应满足：

1. 用户页桌面端看起来比当前更完整、更正式、更高端
2. 首页到子页面之间的品牌感更统一
3. 顾问页、年度页、案例页在 PC 上不再显得松散或像移动端硬放大
4. `partner/profile` 页面不再暴露明显的占位开发信息
5. 手机端不出现明显回退或错乱

## 9. 实施顺序

建议执行顺序：

1. 先删掉 `partner/profile` 中不该展示的占位内容
2. 再处理顾问页桌面端
3. 再处理年度顾问页与案例页桌面端
4. 再处理首页桌面端整体收口
5. 最后处理 `guide-form` 静态页桌面端统一

这样可以先清掉明显问题，再做全局收口。
